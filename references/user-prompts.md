# Project Code Study：场景化提示词包

这是一组用于调用 `project-code-study` 的短提示词，不是另一份 Skill 协议。Skill 已经包含完整工作流；提示词只需要说明当前目标、必要上下文、本轮输出、边界和验证方式。

## 使用方式

- 首次调用时优先显式写出 `$project-code-study`；已经进入同一学习任务后，后续提示词可以更短。
- 将 `<...>` 替换为真实内容；没有的信息直接删除，不必填满所有字段。
- 本地项目尽量提供项目根路径；论文、配置、日志或目标文件只有在会改变结果时才附上。
- 不要在每轮粘贴完整学习日志或长篇角色提示。让 Skill 按需读取热状态和相关记录。
- 提示词中的“本轮边界”用于控制一次只学习一个节点；不要把多个学习阶段塞进同一轮。

宿主不支持 `$skill-name` 语法时，使用宿主的 Skill 选择器，或者直接说“请使用 project-code-study Skill”。

---

## 1. 最短启动方式

适合项目已经位于当前工作区、目标也比较明确时。

```text
请使用 $project-code-study 带我学习当前项目。

目标：<读懂 / 复现 / 修改 / 研究扩展>
我的基础：<一句话说明>

请先确认学习记录权限，检查项目证据并生成项目专属路线。本轮只完成 Step 0。
```

## 2. 完整建立学习任务

适合第一次学习、跨会话学习或材料较多的项目。

```text
请使用 $project-code-study 建立一个新的源码学习任务。

<学习任务>
项目：<本地根目录或 GitHub URL>
目标：<读懂 / 复现 / 修改 / 研究扩展>
我的基础：<语言、框架、数学和领域基础>
每轮时间：<例如 20 分钟>
相关材料：<论文、文档、配置、运行日志；没有则删除>
</学习任务>

请按以下顺序执行：
1. 先询问我是否授权创建或维护 PROJECT_STUDY_LOG.md 和 PROJECT_STUDY_QA.md。
2. 授权后扫描相关源码，确认入口、配置、数据、模型、目标函数、训练、推理和评估证据。
3. 生成项目专属的运行场景路线和概念依赖，不要套用固定模型目录。
4. 本轮只完成 Step 0，不提前讲解 Step 1。

结束时给出：当前 Step、证据边界、主要缺口、唯一下一行动和保存回执。
```

## 3. 只查看或重建学习路线

适合路线过于笼统、顺序不符合源码调用关系，或者 Step 3/4.x 粒度失控时。

```text
请使用 $project-code-study 重新检查当前学习路线。

目标：按真实运行时调用关系重建后续路线。
重点场景：<训练 / 推理 / 评估 / 导出 / 部署；按项目实际保留>

请重新扫描相关源码并输出：
1. 每个场景的入口和调用顺序；
2. 共享节点、场景专属节点和概念前置依赖；
3. 一次一个调用节点、类或函数的动态微 Step；
4. 当前路线遗漏、顺序错误或粒度过大的地方。

本轮边界：只展示并更新路线，不开始新的源码节点讲解。
```

## 4. 继续主线：一次一个节点

```text
请使用 $project-code-study 继续主线。

从 PROJECT_STUDY_LOG.md 的主线学习锚点和“精确继续位置”恢复。本轮只学习一个运行时调用节点、类或函数，并说明它的上游、下游、源码位置、关键输入输出、Shape/状态变化、局部机制和设计原因。

结束前：
- 给我一个用于验证理解的回忆、追踪、Shape 或修改预测问题；
- 不要自动进入下一个节点；
- 更新相关记录并给出保存回执和精确继续位置。
```

## 5. 支线问题：回答后返回主线

```text
这是当前节点的支线问题：

<问题>

请完整回答并创建新的 Q-ID。说明答案依据、它与当前节点的关系，以及是否改变了已有结论或掌握状态。若需要修正旧说法，请记录规范表述并标记受影响内容。

本轮不要推进主线。最后直接告诉我应从哪个场景、Step 和节点继续。
```

## 6. 连续提问模式

适合在同一个 Step 内连续询问多个语法、Shape、公式或设计问题，避免每次回答后丢失主线位置。

```text
我接下来会围绕当前节点连续提问。

在我说“问题结束，继续主线”之前：
1. 每个实质性新问题或追加追问都分配并保存 Q-ID；
2. 完整回答，但不要推进到下一个学习节点；
3. 保持主线学习锚点不变；
4. 每次回答结尾只报告当前锚点和保存回执。

第一个问题：<问题>
```

结束连续提问并恢复时，只需发送：

```text
问题结束，继续主线。请从已保存的主线学习锚点恢复，不要让我向上翻找聊天记录。本轮仍只学习一个节点。
```

## 7. 回答主动回忆或检查题

```text
我的回答：

<回答>

请按照 project-code-study 的问答闭环评价：
1. 判断为正确、部分正确、错误或证据不足；
2. 指出正确部分和缺失/错误部分；
3. 无论我是否答对，都给出完整参考答案；
4. 给出源码、论文或运行证据；
5. 更新掌握度、Q&A 和受影响的旧结论。

只有达到当前节点完成门槛时才安排下一个节点，否则给出最小补强任务。
```

## 8. 要求核查并修正旧说法

```text
请核查你之前关于当前项目的这段说法：

<旧说法或我的质疑>

不要因为我提出质疑就直接同意。请重新检查对应源码、论文或运行证据，然后给出：原说法、核查结论、规范表述、证据、置信度、影响的 Step/Node/Q-ID，以及需要标记 stale 或重新测试的内容。

更新 PROJECT_STUDY_LOG.md 和 PROJECT_STUDY_QA.md 后给出保存回执，主线位置保持不变。
```

## 9. 中断后恢复学习

```text
请使用 $project-code-study 恢复这个项目的学习。

先读取主日志热状态、当前路线行、最近会话、阻塞项、到期复习和当前任务相关的 Q&A；不要默认加载全部历史。

先给我一个 60 秒恢复摘要：
- 当前场景、Step 和节点；
- 已掌握内容与证据；
- 未解决问题或 stale 修正；
- 精确继续位置。

如果存在必须先复习的内容，先安排一次最小复习；否则本轮只继续一个节点。
```

## 10. 定向复习

```text
请使用 $project-code-study 复习：<Step / Node ID / Q-ID / 知识主题>。

先读取相关知识卡、问题、修正和掌握证据。本轮一次只问一个有区分度的问题，优先使用调用追踪、Shape 推演、公式解释或修改预测，而不是只问定义。

我回答后必须得到完整参考答案和证据，再更新复习状态。不要自动切换到新知识。
```

## 11. 论文—代码映射

```text
请使用 $project-code-study 对齐一个论文概念与当前实现。

论文或文档：<路径、URL 或章节>
概念/公式：<名称或位置>
当前节点：<Step / Node；未知则让 Skill 定位>

请区分论文主张、当前代码、运行证据和背景知识，给出概念/公式到源码符号、配置、输入输出和 Shape 的映射，并明确实现差异、证据状态和复现影响。

本轮只完成这一项映射；不要顺带展开整篇论文或整个模型。
```

## 12. 相关方法对比与研究延伸

```text
请使用 $project-code-study 围绕当前知识节点做一次受控对比与延伸。

当前节点或机制：<Step / Node / 机制>
我的目的：<加深理解 / 寻找改进方向 / 设计实验>

请从以下层次中选择真正有学习价值的少量对象：
- 同任务方法；
- 同瓶颈方法；
- 其他任务或领域中的相似思想；
- 可组合模块。

每个对象都说明：为什么相关、共享的抽象、关键差异或不兼容点、需要的证据，以及一个可证伪的验证实验。不要把工程组合直接称为创新。

本轮边界：对比服务于当前主线，不改变主线锚点。
```

## 13. 专门分析模块“缝合”

```text
请使用 $project-code-study 评估这个模块组合：

基础项目/模块 A：<内容>
候选模块 B：<内容>
目标改进：<内容>

请检查接口和 Shape、数据语义、目标函数、梯度/优化稳定性、训练与推理成本、已有工作、失败风险、对照组和消融实验。最后分别判断：
1. 工程上是否可集成；
2. 研究上是否可能形成贡献；
3. 最小可证伪实验是什么。

结论必须标注证据状态，不要仅根据模块名称推断兼容。
```

## 14. 进入复现或运行验证

```text
请使用 $project-code-study 为当前项目建立最小复现路径。

目标：<只跑通推理 / 复现指标 / 训练最小样例 / 验证某个节点>
可用资源：<环境、设备、数据、权重>
权限边界：<允许或不允许安装依赖、下载、运行命令、修改文件>

请先列出环境、版本、数据、配置、权重、入口命令、随机性和评估协议，再给出最小验证顺序。区分已经运行的证据与建议执行的命令；未获得授权时不要执行有副作用的操作。

将成功、失败、命令、输出和解释记录到学习日志，并说明它们改变了哪些结论。
```

## 15. 提交教学反馈

```text
这是我对当前学习方式的反馈：

<反馈>

请将它记录为教学反馈，说明影响的 Step/Node、你准备如何调整粒度、顺序、解释方式或验证任务。不要因为调整教学方式而丢失当前主线锚点。

本轮先确认调整方案和保存回执；除非我明确要求，否则不要立即开始下一节点。
```

## 16. 全局覆盖与盲点审计

```text
请使用 $project-code-study 执行一次全局覆盖审计。

重新检查：
- 训练、推理、评估等实际运行场景；
- 核心调用节点和概念依赖；
- Step 知识卡和掌握证据；
- 用户问题、追加追问和规范修正；
- 数据/Shape、目标函数、论文代码映射和运行证据；
- 相关方法、复现与实验缺口。

输出遗漏项、影响、证据和回补顺序。发现缺口时插入回补微 Step，不要把未学内容追认成 done。本轮只完成审计和路线更新。
```

## 17. 所有 Step 完成后继续提问

```text
所有计划 Step 已经完成，但我还有问题。

请继续按照 Q-ID、完整答案、证据、修正和保存回执的规则处理问题；不要询问或生成最终学习文档，直到我明确说“没有更多问题”。

问题：<问题>
```

## 18. 结束问题阶段，进入文档生成确认

```text
我这一轮没有更多问题了。

请先执行最终文档就绪检查：动态 Step、运行场景、核心节点、概念依赖、掌握证据、开放问题、待回答回忆题、修正和 stale 结论是否全部满足要求。

如果未满足，只报告阻塞项和最小回补行动；如果全部满足，再询问我一次是否生成 PROJECT_STUDY_DOCUMENT.md。不要根据这条消息自动生成文档。
```

## 19. 明确同意生成最终学习文档

只有在完成全部学习、关闭问题阶段并收到生成询问后使用。

```text
我确认没有更多问题，并同意现在生成 PROJECT_STUDY_DOCUMENT.md。

请调用 project-study-document 伴生 Skill，完整读取 PROJECT_STUDY_LOG.md 和 PROJECT_STUDY_QA.md，并重新核验高影响结论。

生成要求：
- 每个 done Step/微 Step 都保留知识覆盖行并映射到至少一个 UNIT 复习单元；
- 文档必须让我在忘记原对话后仍能重新学会各 Step 的知识；
- 纳入真正改变理解的重要用户提问、完整规范答案和修正；
- 正文按真实调用关系和概念依赖组织，不写成聊天流水账；
- 区分已确认、可推断、背景知识和待验证；
- 保留失败、局限、未解决事项、复现证据和后续行动；
- 若目标文件已存在，先询问更新还是创建带日期副本，不要静默覆盖。

写入后运行：
python skills/project-study-document/scripts/validate_study_document.py PROJECT_STUDY_DOCUMENT.md --ledger PROJECT_STUDY_LOG.md

最后报告文件路径、仓库版本、覆盖数量、验证结果和剩余局限。
```

## 20. 仅生成未完成草稿

适合学习尚未完成，但用户确实需要阶段性材料时。

```text
请使用 $project-code-study，并调用 bundled project-study-document 生成一份阶段性学习文档草稿，而不是完整最终文档。

我知道当前路线尚未完成。请将 frontmatter 和标题明确标记为 incomplete-draft，列出所有缺失 Step、未回答问题、证据缺口和不能声称的能力；已经覆盖的知识仍按 Step 索引和 UNIT 复习单元组织。

目标文件：<路径；如省略则先询问>
```

## 21. 宿主没有 Skill 选择器

如果宿主可以读取本地文件，优先让它加载真实 Skill，而不是复制一份容易过期的长提示词：

```text
请完整读取并遵循 <project-code-study 安装目录>/SKILL.md，然后按其中的 Required Resources 按需读取引用文件。

任务：带我学习 <项目路径或 URL>
目标：<读懂 / 复现 / 修改 / 研究扩展>
本轮边界：先确认记录权限并只完成 Step 0。
```

只有在宿主既不支持 Skill、也不能读取 Skill 文件时，才使用下面的最小兼容提示：

```text
请按真实运行路径带我逐步学习项目。先扫描相关源码，分别识别训练、推理和评估入口，再生成一次一个调用节点、类或函数的学习路线。

维护两个记录：主日志只保存路线、当前锚点、证据、掌握度和修正索引；Q&A 文件保存全部实质问题、追问、完整答案和反馈。每次写入后回读验证。

每轮只学习一个节点；支线问题不能移动主线锚点；我回答检查题后，无论对错都要得到完整参考答案和证据；只有行为证据才能把 Step 标为完成。未读取的实现不得猜测。

项目：<路径或 URL>
目标：<目标>
本轮：只完成 Step 0。
```

## 不推荐的提示方式

| 不推荐写法 | 问题 | 建议替换 |
| --- | --- | --- |
| “把整个项目详细讲一遍” | 范围和完成标准不清，容易变成长架构概述 | 指定目标，并要求本轮只完成一个 Step 或节点 |
| “继续” | 跨会话时缺少恢复依据 | 要求从主线学习锚点和精确继续位置恢复 |
| 每轮粘贴完整日志 | 浪费上下文并可能覆盖真实热状态 | 让 Skill 读取热状态和相关 ID |
| “给我推荐一些类似模型” | 对比目的和边界不清 | 指定当前机制、比较目的和可证伪实验 |
| 学完最后一个编号就直接要求总结 | 可能遗漏问题、修正和动态回补 Step | 先关闭问题阶段，再明确同意生成最终文档 |
| “我的想法对吗？” | 容易得到没有证据的迎合 | 要求重新核查证据、给出规范表述和可推翻条件 |

## 官方设计依据

本提示词包遵循以下官方建议：

- [OpenAI Prompting](https://developers.openai.com/codex/prompting)：重要任务应明确目标、上下文、输出和边界；Codex 任务还应指出相关代码或材料、保留约束并说明验证方式。
- [OpenAI Build skills](https://developers.openai.com/codex/skills)：Skill 可通过 `$skill-name` 显式调用；完整协议由 Skill 按需加载，提示词无需重复全部说明。
- [OpenAI Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering)：使用 Markdown 标题、列表或 XML 标签区分指令、上下文和变量输入。
- [Anthropic Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)：使用清晰直接的指令，提供必要上下文，在顺序或完整性重要时使用编号步骤，并用结构化标签分隔复杂输入。
- [Agent Skills specification](https://agentskills.io/specification) 与 [Best practices](https://agentskills.io/skill-creation/best-practices)：利用渐进披露保持主 Skill 与用户提示精简，把详细、按需内容放入引用文件。
