# Project Code Study：恢复与诊断提示

这些短提示用于启动、恢复、审计或明确边界。Q-ID、回答后暂停、单次 `继续`、原子事务和完成门槛是 Skill 内部不变量，用户不需要反复粘贴控制条款。

宿主支持 Skill 选择器时优先显式使用 `$project-code-study`；否则直接要求读取安装目录中的 `SKILL.md`。

## 1. 启动学习

```text
请使用 $project-code-study 带我学习当前项目。
目标：<读懂 / 复现 / 修改 / 研究扩展>
基础：<一句话>
本轮先确认记录权限、证据边界和项目专属路线，只完成 Step 0。
```

## 2. 从记录恢复

```text
请使用 $project-code-study 从 PROJECT_STUDY_LOG.md 的权威热状态恢复。
先给 60 秒摘要，再按 interaction_state 执行唯一下一行动。
```

## 3. 继续一个节点

```text
继续主线。本轮只学习精确继续位置对应的一个 NODE。
```

## 4. 重建路线

```text
请重新扫描相关源码，按实际项目分别建立训练、推理、评估等 RUN 调用图和概念依赖。
列出每个 NODE 的独立状态与跳过/延后影响。本轮只更新路线，不开始教学。
```

## 5. 支线问题

```text
当前节点的问题：<问题>
```

Skill 必须自行分配 Q-ID、保持主线锚点、保存完整答案并在回答后暂停；无需在提示中重复要求。

## 6. 核查旧说法

```text
请重新核查这段说法：<旧说法或质疑>
给出证据状态、规范表述、影响范围和需要回测的内容，主线保持不变。
```

## 7. 定向复习

```text
请复习 <Step / NODE / Q / K ID>，优先使用调用追踪、Shape/状态推演或修改预测。
```

## 8. 论文—代码映射

```text
请把 <论文概念/公式/章节> 与当前实现对齐。
区分论文主张、代码证据、运行证据和背景知识；本轮只完成这一项映射。
```

## 9. 模块组合评估

```text
请评估 <模块 A> 与 <模块 B> 的组合，目标是 <目标>。
分别判断工程可集成性、研究贡献可能性和最小可证伪实验。
```

## 10. 复现与运行验证

```text
请建立 <推理 / 指标 / 最小训练 / NODE> 的最小验证路径。
可用资源：<环境、设备、数据、权重>
权限：<安装、下载、运行、修改边界>
```

## 11. 全局覆盖审计

```text
请执行全局覆盖审计，检查 RUN/NODE/依赖、K 卡、Q/M/C、Shape、目标函数、论文映射和运行证据。
只报告缺口、影响和回补顺序，不把未学内容追认成 done。
```

## 12. 关闭问题阶段

```text
这一轮没有更多问题了。请运行最终化 readiness audit；若有阻塞只报告阻塞和最小回补动作。
```

这不会自动生成文档。只有 readiness 通过后，Skill 才会单独询问是否生成。

## 13. 明确生成

```text
我明确同意现在生成 PROJECT_STUDY_DOCUMENT.md。
```

仅当问题阶段已经明确关闭且 readiness 通过时有效。

## 14. 未完成草稿

```text
我知道路线尚未完成，但需要阶段性文档。请只生成 incomplete-draft，并列出全部 readiness 阻塞项。
```

## 15. 宿主没有 Skill 选择器

```text
请完整读取并遵循 <安装目录>/project-code-study/SKILL.md，再按 Required resources 按需完整读取引用文件。
任务：学习 <项目路径或 URL>
目标：<目标>
本轮：只建立证据边界与路线。
```

## 诊断清单

行为异常时可发送：

```text
请停止推进并诊断当前记录：
1. frontmatter 与热状态是否一致；
2. interaction_state 和 pending_user_response 是否允许推进；
3. current/continuation NODE 是否唯一；
4. 最近 Q/TX 是否在 LOG 与 QA 中一致；
5. 最近回执是否真的通过回读与 strict validator。
只修复记录一致性，不开始新教学。
```

## 不推荐

| 写法 | 问题 | 替代 |
| --- | --- | --- |
| “把整个项目讲一遍” | 无完成边界 | 指定目标并一次一个 NODE |
| 跨会话只说“继续” | 可能缺恢复上下文 | 明确从权威热状态恢复 |
| 每轮粘贴完整日志 | 浪费上下文且易覆盖状态 | 让 Skill 选择性读取 |
| 学完最后编号就直接总结 | 动态回补和问题可能未闭合 | 先运行 readiness audit |
| 反复粘贴“创建 Q-ID、不要推进” | 把内部不变量转嫁给用户 | 直接提问；异常时运行诊断 |
