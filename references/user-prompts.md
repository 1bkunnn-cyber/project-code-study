# User Prompt Pack for `$project-code-study`

This is a user-facing auxiliary document, not a skill. Copy these prompts into a new conversation when you want to invoke or steer `$project-code-study`.

Replace text inside `<...>` before use.

## 1. 第一次对话完整开场提示词

```text
请使用 $project-code-study 帮我以计算机专业研究生的深度学习这个项目源码。

我的目标不是只听一个泛泛的项目介绍，而是希望你基于真实项目文件、论文和代码证据，按 step 带我逐步读懂项目，最终让我能做到：
1. 讲清楚项目解决的问题、论文动机和核心方法；
2. 读懂关键源码，包括参数、调用关系、语法、shape 变化、模块作用和模块关系；
3. 理解训练、推理、损失函数、评价指标和复现实验；
4. 发现我可能忽视但很重要的点；
5. 最后生成一份完整 Markdown 学习笔记。

在正式开始前，请先做三件事：
1. 询问我是否授权你在项目文件夹中创建/维护学习记录文档 `PROJECT_STUDY_LOG.md`；
2. 要求我提供项目文件夹路径，或提供一个可写保存位置；
3. 检查当前材料是否足够。如果缺少项目文件、README、配置、训练/推理入口、模型代码、数据处理代码、论文 PDF 或论文链接，请先明确要求我补充，不要凭记忆直接讲解源码。

学习过程中请严格遵守：
- 所有结论尽量给出证据来源，例如文件路径、函数名、类名、配置项、论文页码/章节/公式；
- 没有证据时必须说“当前材料中未看到证据”；
- 区分“经典模型/论文背景常识”和“当前项目源码证据”；
- 每个 step 结束后更新学习记录文档或临时学习记录；
- 每个 step 开始前回看学习记录，调整本 step 的讲解重点；
- 如果我提问，请回答后把重要问题写入学习记录，最终总结时纳入 Markdown 笔记。

项目材料：
- 项目路径或仓库链接：<项目路径或 GitHub 链接>
- 论文 PDF/链接：<论文 PDF、arXiv、DOI 或 README 中的论文链接>
- 我当前最想先弄懂的问题：<你的问题，可留空>
```

## 2. 已经有项目文件夹和论文时

```text
请使用 $project-code-study 学习这个项目。

我授权你在项目根目录创建或更新 `PROJECT_STUDY_LOG.md` 作为学习记录文档。请先读取项目结构、README、配置文件、训练/推理入口、模型定义、数据处理代码，并结合我提供的论文材料建立证据清单。

项目路径：<项目文件夹路径>
论文材料：<论文 PDF 路径或链接>

请先输出 Step 0：项目地图。要求包括：
- 目录结构和核心文件；
- 训练、推理、评估入口；
- 模型、数据、loss、metric、config 的大致位置；
- 论文来源和当前证据范围；
- 你当前没有把握的点；
- 你建议我接下来优先学习的路线。

不要一次性讲完整个项目。Step 0 结束后请更新 `PROJECT_STUDY_LOG.md` 并等待我说“继续”。
```

## 3. 材料还不完整时

```text
请使用 $project-code-study 帮我开始学习项目，但我现在材料可能不完整。

请你先不要讲解模型细节，而是先检查我提供的信息是否足够进行源码级学习。请列出：
1. 当前已有材料；
2. 缺少哪些关键材料；
3. 哪些缺失会阻碍你准确讲解；
4. 我最少需要上传哪些文件或文件夹；
5. 是否需要论文 PDF、README 或配置文件。

如果当前材料不足，请明确要求我补充，不要根据常识或记忆编造当前项目实现。

当前我能提供的信息：
<粘贴项目链接、文件列表、部分代码或描述>
```

## 4. 继续下一 Step

```text
继续使用 $project-code-study 进入下一 step。

在开始前，请先回看 `PROJECT_STUDY_LOG.md` 或临时学习记录，并说明：
1. 上一个 step 的核心结论；
2. 仍未解决的问题；
3. 当前证据缺口；
4. 本 step 需要重点关注什么；
5. 是否需要调整原学习路线。

然后只讲解一个 step，不要跳太远。讲解结束后请更新学习记录，并告诉我下一 step 建议学什么。
```

## 5. 指定学习某个 Step 或模块

```text
请使用 $project-code-study 学习 <step 编号或模块名称>。

本次请重点讲：
- 参数定义；
- 代码逻辑；
- 调用关系；
- Python/PyTorch 语法；
- shape 变化；
- 模块在整体架构中的作用；
- 与论文的对应关系；
- 工程实现细节；
- 易错点和调试方法。

请基于当前项目文件和论文证据讲解。没有证据的地方请标注“当前材料中未看到证据”。讲完后请更新学习记录文档。
```

## 6. 要求本 Step 讲得更深入

```text
刚才这个 step 我觉得还不够深入。请继续使用 $project-code-study 对当前 step 做研究生级加深讲解。

请从以下角度补充：
1. 这段代码为什么这样设计，而不是只说它做了什么；
2. 关键参数改变后会影响什么；
3. 每个重要 tensor 的 shape 如何变化；
4. 当前实现与论文是否完全一致；
5. 这段实现有什么工程取舍；
6. 如果我要复现或修改它，最容易踩哪些坑；
7. 这个模块和上下游模块的关系是什么；
8. 还有哪些我可能没有意识到但应该追问的问题。

请把新增理解、疑问和建议写入学习记录。
```

## 7. 用户附加提问模板

```text
这是我在当前 step 的追问，请使用 $project-code-study 回答，并把重要内容记录到 `PROJECT_STUDY_LOG.md`：

问题：<你的问题>

回答时请分成：
1. 基于当前项目证据的回答；
2. 通用背景知识或论文常识；
3. 当前材料中没有证据的部分；
4. 如果要确认，需要继续看哪些文件、代码或论文部分；
5. 这个问题是否应该进入最终 Markdown 学习笔记。
```

## 8. 要求纠错或防幻觉复查

```text
请使用 $project-code-study 重新检查你刚才的回答是否有证据不足或可能幻觉的地方。

请逐条列出：
1. 哪些结论有明确代码/论文证据；
2. 哪些结论只是通用背景知识；
3. 哪些地方当前材料中未看到证据；
4. 是否有文件、函数、参数、实验结果或论文结论可能被你误认为存在；
5. 为了确认这些点，我应该提供哪些文件或你应该继续检查哪些路径。

请把修正后的不确定事项写入学习记录。
```

## 9. 要求重新查看上下文并调整路线

```text
请使用 $project-code-study 暂停当前讲解，先重新查看上下文和 `PROJECT_STUDY_LOG.md`。

请回答：
1. 到目前为止我已经学到了什么；
2. 哪些问题反复出现，说明我还没真正掌握；
3. 哪些重要点被我忽视了；
4. 哪些地方你作为 AI 仍然没有把握；
5. 下一 step 是否应该调整；
6. 如果要提高学习效率，我应该先补充什么材料或先问什么问题。

请更新学习记录中的“路线调整日志”“AI 不确定事项”“用户可能忽视的点”和“下一步学习建议”。
```

## 10. Step 9 全局盲点审计

```text
请使用 $project-code-study 执行 Step 9：全局上下文审视与盲点审计。

请重新检查项目结构、已读代码、论文证据、用户提问和 `PROJECT_STUDY_LOG.md`，然后输出：
1. 仍然重要但尚未学习或被低估的点；
2. 你当前没有把握的事情，以及缺少什么证据；
3. 当前学习状态下最大的遗憾或缺口；
4. 我可能还没有意识到的问题；
5. 哪些问题会影响复现、理解论文或修改代码；
6. 下一步补强建议，包括要上传的文件、要运行的命令、要补读的论文部分和要追踪的函数。

请把这次审计结果写入学习记录，并标记哪些内容应进入最终 Markdown 学习笔记。
```

## 11. 生成最终 Markdown 学习笔记

```text
请使用 $project-code-study 生成最终 Markdown 学习笔记。

请优先基于 `PROJECT_STUDY_LOG.md` 和我们所有 step 的学习记录，不要只根据最后一轮对话总结。最终文档请包含：
1. 项目概览和证据范围；
2. 论文背景与核心思想；
3. 学习路线和每个 step 的核心收获；
4. 模块关系和调用关系；
5. 关键代码精读；
6. shape 流；
7. 论文-代码映射；
8. 数据、训练、推理、评价和复现；
9. 全局盲点审计；
10. 用户问题与回答；
11. 易错点和调试清单；
12. 术语表；
13. 后续阅读和实验建议。

请明确标注仍缺少证据或未确认的地方，不要把不确定内容写成事实。
```

项目路径/链接：<项目路径或链接>
论文：<论文路径或链接>
